# **Polymorphism in Java**

**Polymorphism** is a key concept in object-oriented programming (OOP) that allows objects to take on multiple forms. In Java, polymorphism enables methods to perform different tasks based on the context. It simplifies code by providing a unified interface to interact with objects of different types.

Polymorphism is divided into two types:
1. **Compile-time Polymorphism** (also known as static polymorphism)
2. **Runtime Polymorphism** (also known as dynamic polymorphism)

---

## **1. What is Polymorphism?**

The word **polymorphism** comes from the Greek words "poly" (many) and "morph" (forms). It means the ability of a single interface or method to represent multiple forms or behaviors.

### **Key Features**
- **Reusability**: Write general code that works with objects of different types.
- **Extensibility**: Add new classes or behaviors without changing existing code.
- **Flexibility**: Dynamically determine which method or behavior to execute.

---

## **2. Compile-Time Polymorphism (Static Polymorphism)**

**Compile-time polymorphism** occurs when the method to be executed is determined at compile time. It is achieved using **method overloading** or **operator overloading** (not supported in Java).

---

### **2.1. Method Overloading**

**Method overloading** allows multiple methods in the same class to have the same name but different parameter lists.

---

**Example: Method Overloading**
```java
public class Calculator {
    // Overloaded methods
    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {
        return a + b;
    }

    public int add(int a, int b, int c) {
        return a + b + c;
    }

    public static void main(String[] args) {
        Calculator calc = new Calculator();
        System.out.println("Sum (int, int): " + calc.add(10, 20));
        System.out.println("Sum (double, double): " + calc.add(10.5, 20.5));
        System.out.println("Sum (int, int, int): " + calc.add(10, 20, 30));
    }
}
```

**Output:**
```
Sum (int, int): 30
Sum (double, double): 31.0
Sum (int, int, int): 60
```

---

### **Key Characteristics of Compile-Time Polymorphism**

1. Determined during **compilation**.
2. Achieved through **method overloading**.
3. Does not involve inheritance.

---

## **3. Runtime Polymorphism (Dynamic Polymorphism)**

**Runtime polymorphism** occurs when the method to be executed is determined at runtime. It is achieved using **method overriding** in conjunction with **inheritance**.

---

### **3.1. Method Overriding**

**Method overriding** allows a subclass to provide a specific implementation of a method already defined in its superclass. At runtime, the method called is determined by the object's actual type, not the reference type.

---

**Example: Method Overriding**
```java
class Animal {
    void sound() {
        System.out.println("This is a generic animal sound.");
    }
}

class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks.");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows.");
    }
}

public class RuntimePolymorphismExample {
    public static void main(String[] args) {
        Animal myAnimal;

        myAnimal = new Dog();
        myAnimal.sound(); // Calls Dog's sound method

        myAnimal = new Cat();
        myAnimal.sound(); // Calls Cat's sound method
    }
}
```

**Output:**
```
Dog barks.
Cat meows.
```

---

### **3.2. Real-World Analogy**

A single method `sound()` can perform different behaviors depending on the actual type of the object (Dog, Cat, or Animal).

---

### **Key Characteristics of Runtime Polymorphism**

1. Determined during **execution**.
2. Achieved through **method overriding**.
3. Requires **inheritance** and **dynamic method dispatch**.

---

## **4. Method Overloading vs Method Overriding**

| **Aspect**              | **Method Overloading**                              | **Method Overriding**                               |
|--------------------------|----------------------------------------------------|---------------------------------------------------|
| **Definition**           | Multiple methods with the same name but different parameters. | Subclass provides a specific implementation of a superclass method. |
| **Polymorphism Type**    | Compile-time polymorphism                          | Runtime polymorphism                              |
| **Inheritance**          | Not required                                       | Required                                          |
| **Parameters**           | Must differ                                        | Must match                                        |
| **Access Modifiers**     | Can vary                                           | Cannot reduce visibility                         |

## **5. Polymorphism with Interfaces**

Polymorphism can also be achieved using **interfaces**, allowing different classes to implement the same interface and define their own behavior.

**Example: Polymorphism with Interfaces**
```java
interface Shape {
    void draw();
}

class Circle implements Shape {
    @Override
    public void draw() {
        System.out.println("Drawing a Circle.");
    }
}

class Rectangle implements Shape {
    @Override
    public void draw() {
        System.out.println("Drawing a Rectangle.");
    }
}

public class InterfacePolymorphismExample {
    public static void main(String[] args) {
        Shape shape;

        shape = new Circle();
        shape.draw(); // Calls Circle's draw method

        shape = new Rectangle();
        shape.draw(); // Calls Rectangle's draw method
    }
}
```

**Output:**
```
Drawing a Circle.
Drawing a Rectangle.
```

---

## **6. Advantages of Polymorphism**

1. **Code Reusability**:
   - Common functionality can be written in the superclass or interface.
2. **Extensibility**:
   - New subclasses can easily add or override behavior without modifying existing code.
3. **Simplified Maintenance**:
   - Unified interface for interacting with objects of different types.

---

## **7. Practical Use Case: Vehicle Example**

**Problem:** Different types of vehicles (Car, Bike, Truck) must start differently.

**Solution:**
```java
class Vehicle {
    void start() {
        System.out.println("Vehicle is starting.");
    }
}

class Car extends Vehicle {
    @Override
    void start() {
        System.out.println("Car starts with ignition.");
    }
}

class Bike extends Vehicle {
    @Override
    void start() {
        System.out.println("Bike starts with a kick.");
    }
}

public class PolymorphismExample {
    public static void main(String[] args) {
        Vehicle vehicle;

        vehicle = new Car();
        vehicle.start(); // Calls Car's start method

        vehicle = new Bike();
        vehicle.start(); // Calls Bike's start method
    }
}
```

**Output:**
```
Car starts with ignition.
Bike starts with a kick.
```

## **8. Common Mistakes**

1. **Confusing Overloading and Overriding**:
   - Overloading is compile-time; overriding is runtime.
2. **Static Methods in Polymorphism**:
   - Static methods are not polymorphic; they are resolved at compile time.

**Example: Static Method Behavior**
```java
class Parent {
    static void display() {
        System.out.println("Parent display method.");
    }
}

class Child extends Parent {
    static void display() {
        System.out.println("Child display method.");
    }
}

public class StaticExample {
    public static void main(String[] args) {
        Parent parent = new Child();
        parent.display(); // Calls Parent's method
    }
}
```

**Output:**
```
Parent display method.
```

---

## **9. Best Practices**

1. **Use Interfaces for Flexibility**:
   - Prefer interfaces when multiple classes need polymorphic behavior.
2. **Follow Liskov Substitution Principle**:
   - Subclasses should be able to replace the superclass without affecting functionality.
3. **Leverage @Override**:
   - Always use `@Override` annotation to avoid accidental overloading instead of overriding.

---

## **10. Summary**

- **Polymorphism** allows methods or objects to behave differently depending on their context or type.
- **Compile-time Polymorphism**:
  - Achieved using **method overloading**.
  - Determined at compile time.
- **Runtime Polymorphism**:
  - Achieved using **method overriding**.
  - Determined at runtime via dynamic method dispatch.
- **Advantages**:
  - Improves code reusability, flexibility, and maintainability.

Polymorphism is a cornerstone of object-oriented programming, making applications more modular and extensible. Mastering polymorphism ensures robust and scalable software design.
