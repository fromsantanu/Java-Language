# **Garbage Collection in Java**

**Garbage Collection (GC)** in Java is the process of automatically identifying and reclaiming memory occupied by objects that are no longer in use. This is a key feature of Java's memory management system, ensuring efficient use of the heap memory and reducing the likelihood of memory leaks.

---

## **1. What is Garbage Collection?**

Garbage collection is an automatic process managed by the **Java Virtual Machine (JVM)** that:
1. **Identifies unused objects**: Objects that are no longer accessible from any reference.
2. **Reclaims memory**: Frees up heap memory occupied by these objects.
3. **Prevents memory leaks**: Ensures that unused objects do not consume memory indefinitely.

### **Key Features of Garbage Collection**
- **Automatic**: No need for manual memory management (unlike languages like C/C++).
- **Transparent**: The developer does not control when GC occurs.
- **Managed by JVM**: The JVM runs the garbage collector as needed.

---

## **2. How Garbage Collection Works**

### **2.1. Heap Memory Segments**
The JVM divides heap memory into segments for efficient garbage collection:
- **Young Generation**:
  - New objects are allocated here.
  - Contains three regions:
    1. **Eden Space**: Where new objects are created.
    2. **Survivor Space 1** and **Survivor Space 2**: Holds objects that survive garbage collection in Eden.
- **Old Generation**:
  - Stores objects that have existed for a long time and survived multiple GC cycles in the Young Generation.
- **Metaspace**:
  - Stores class metadata.

---

### **2.2. Object Lifecycle**
1. **Creation**:
   - Objects are created in the Eden Space of the Young Generation.
2. **Promotion**:
   - If an object survives several garbage collection cycles in the Young Generation, it is moved (promoted) to the Old Generation.
3. **Collection**:
   - Unreachable objects in the heap are collected during garbage collection.

---

### **2.3. Identifying Unreachable Objects**
Java uses **object references** to determine if an object is reachable. If no active references point to an object, it is considered unreachable and eligible for garbage collection.

**Example: Unreachable Object**
```java
public class GarbageExample {
    public static void main(String[] args) {
        String str = new String("Hello, World!"); // Object in heap
        str = null; // Object becomes unreachable
        System.gc(); // Suggests garbage collection
    }
}
```

---

## **3. Types of Garbage Collectors**

Java provides several garbage collectors, each suited for specific application needs.

### **3.1. Serial Garbage Collector**
- Uses a single thread for GC.
- Suitable for single-threaded applications.

### **3.2. Parallel Garbage Collector**
- Uses multiple threads for GC.
- Suitable for multi-threaded applications requiring high throughput.

### **3.3. CMS (Concurrent Mark-Sweep) Garbage Collector**
- Performs GC concurrently with the application.
- Reduces pause times but is more CPU-intensive.

### **3.4. G1 (Garbage-First) Garbage Collector**
- Divides the heap into regions.
- Prioritizes regions with the most garbage.
- Balances throughput and pause times.

---

## **4. Phases of Garbage Collection**

### **4.1. Young Generation Collection (Minor GC)**
- Collects garbage in the Young Generation.
- Objects that survive multiple Minor GCs are promoted to the Old Generation.

### **4.2. Old Generation Collection (Major GC/Full GC)**
- Collects garbage in the Old Generation.
- More time-consuming compared to Minor GC.

---

## **5. Invoking Garbage Collection**

While garbage collection is automatic, developers can request it using:
```java
System.gc();
```

**Example:**
```java
public class GCExample {
    public static void main(String[] args) {
        String str = new String("Garbage Collection Example");
        str = null; // Make the object eligible for GC
        System.gc(); // Request garbage collection
        System.out.println("Garbage Collection requested.");
    }
}
```

**Output:**
```
Garbage Collection requested.
```

*Note*: `System.gc()` is only a request. The JVM decides if and when to run the garbage collector.

---

## **6. Finalization**

Java provides a method called `finalize()` to perform cleanup before an object is garbage collected. However, its use is discouraged due to unpredictability and inefficiency.

**Example:**
```java
public class FinalizeExample {
    @Override
    protected void finalize() throws Throwable {
        System.out.println("Object is being garbage collected.");
    }

    public static void main(String[] args) {
        FinalizeExample obj = new FinalizeExample();
        obj = null; // Make the object eligible for GC
        System.gc();
    }
}
```

**Output:**
```
Object is being garbage collected.
```

## **7. Common Misconceptions**

1. **Garbage Collection Eliminates All Memory Leaks**:
   - GC handles unreachable objects but does not prevent improper object references that cause memory leaks.

2. **`System.gc()` Guarantees GC Execution**:
   - It is merely a request, not a guarantee.

3. **Finalized Objects Are Immediately Collected**:
   - Finalization does not ensure immediate collection.

---

## **8. Best Practices for Memory Management**

1. **Avoid Explicit Finalization**:
   - Use `try-with-resources` or `finally` for resource management.
   
2. **Nullify References**:
   - Set unused references to `null` to make objects eligible for GC.

3. **Use Appropriate Data Structures**:
   - Avoid memory leaks by using collections like `WeakHashMap` for cache management.

4. **Optimize Object Creation**:
   - Reuse objects instead of creating unnecessary ones.

5. **Profile Memory Usage**:
   - Use tools like **JVisualVM**, **Eclipse MAT**, or **JProfiler** to monitor memory usage and detect leaks.

---

## **9. Garbage Collection Monitoring**

### **9.1. JVM Options**
- Enable GC logging to monitor garbage collection behavior.
  ```bash
  -XX:+PrintGCDetails -XX:+PrintGCDateStamps
  ```

### **9.2. Example GC Log**
```
[GC (Allocation Failure) [PSYoungGen: 512K->64K(1024K)] 1024K->512K(2048K), 0.0016400 secs]
```

### **9.3. Tools**
- **JVisualVM**: Real-time monitoring of heap usage and GC activity.
- **Eclipse MAT**: Analyzes heap dumps for memory leaks.
