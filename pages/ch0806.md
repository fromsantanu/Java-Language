# **Custom Exceptions in Java**

In Java, exceptions are a vital part of robust error handling. While Java provides a rich hierarchy of built-in exceptions, sometimes specific application scenarios require the creation of **custom exceptions**. Custom exceptions allow developers to define meaningful, domain-specific error messages and behaviors.

---

## **1. What are Custom Exceptions?**

Custom exceptions are user-defined exceptions created by extending existing exception classes like `Exception` or `RuntimeException`. They are tailored to represent specific errors unique to an application.

---

## **2. Why Use Custom Exceptions?**

### **2.1. Domain-Specific Errors**
- Provide meaningful names and messages for specific application errors.

### **2.2. Better Code Readability**
- Enhance clarity by categorizing and identifying errors explicitly.

### **2.3. Consistent Error Handling**
- Simplify error-handling logic across the application.

---

## **3. Creating a Custom Exception**

Custom exceptions are created by extending the `Exception` or `RuntimeException` classes.

### **3.1. Extending the `Exception` Class**

This approach creates a **checked exception**, requiring the caller to handle it explicitly.

**Example: Checked Custom Exception**
```java
// Define custom exception
public class InvalidAgeException extends Exception {
    public InvalidAgeException(String message) {
        super(message);
    }
}

// Use custom exception
public class CheckedExceptionExample {
    public void checkAge(int age) throws InvalidAgeException {
        if (age < 18) {
            throw new InvalidAgeException("Age must be 18 or older.");
        }
    }

    public static void main(String[] args) {
        CheckedExceptionExample example = new CheckedExceptionExample();
        try {
            example.checkAge(15);
        } catch (InvalidAgeException e) {
            System.out.println("Caught exception: " + e.getMessage());
        }
    }
}
```

**Output:**
```
Caught exception: Age must be 18 or older.
```

---

### **3.2. Extending the `RuntimeException` Class**

This approach creates an **unchecked exception**, which does not require explicit handling.

**Example: Unchecked Custom Exception**
```java
// Define custom exception
public class NegativeNumberException extends RuntimeException {
    public NegativeNumberException(String message) {
        super(message);
    }
}

// Use custom exception
public class UncheckedExceptionExample {
    public int squareRoot(int number) {
        if (number < 0) {
            throw new NegativeNumberException("Number must not be negative.");
        }
        return (int) Math.sqrt(number);
    }

    public static void main(String[] args) {
        UncheckedExceptionExample example = new UncheckedExceptionExample();
        try {
            System.out.println(example.squareRoot(-9));
        } catch (NegativeNumberException e) {
            System.out.println("Caught exception: " + e.getMessage());
        }
    }
}
```

**Output:**
```
Caught exception: Number must not be negative.
```

---

## **4. Choosing Between Checked and Unchecked Custom Exceptions**

| **Aspect**            | **Checked Exception** (`Exception`)               | **Unchecked Exception** (`RuntimeException`)   |
|------------------------|---------------------------------------------------|-----------------------------------------------|
| **Purpose**            | Represent recoverable errors.                    | Represent programming errors or logic flaws.  |
| **Handling Requirement** | Must be caught or declared with `throws`.       | Does not require explicit handling.           |
| **Use Case**           | Missing files, invalid inputs.                   | Null references, array bounds errors.         |

## **5. Adding Additional Properties to Custom Exceptions**

Custom exceptions can include additional properties to convey more information about the error.

**Example: Custom Exception with Properties**
```java
// Define custom exception
public class ProductNotFoundException extends Exception {
    private int productId;

    public ProductNotFoundException(String message, int productId) {
        super(message);
        this.productId = productId;
    }

    public int getProductId() {
        return productId;
    }
}

// Use custom exception
public class ProductService {
    public void findProduct(int productId) throws ProductNotFoundException {
        if (productId != 101) { // Assume only product 101 exists
            throw new ProductNotFoundException("Product not found", productId);
        }
        System.out.println("Product found.");
    }

    public static void main(String[] args) {
        ProductService service = new ProductService();
        try {
            service.findProduct(202);
        } catch (ProductNotFoundException e) {
            System.out.println("Error: " + e.getMessage() + " (Product ID: " + e.getProductId() + ")");
        }
    }
}
```

**Output:**
```
Error: Product not found (Product ID: 202)
```

## **6. Custom Exception Hierarchies**

In complex applications, custom exceptions can be organized into hierarchies for better categorization.

**Example: Custom Exception Hierarchy**
```java
// Base custom exception
public class ApplicationException extends Exception {
    public ApplicationException(String message) {
        super(message);
    }
}

// Derived exceptions
public class DatabaseException extends ApplicationException {
    public DatabaseException(String message) {
        super(message);
    }
}

public class ValidationException extends ApplicationException {
    public ValidationException(String message) {
        super(message);
    }
}

// Use exception hierarchy
public class ExceptionHierarchyExample {
    public void connectToDatabase() throws DatabaseException {
        throw new DatabaseException("Database connection failed.");
    }

    public void validateInput(int input) throws ValidationException {
        if (input <= 0) {
            throw new ValidationException("Input must be positive.");
        }
    }

    public static void main(String[] args) {
        ExceptionHierarchyExample example = new ExceptionHierarchyExample();
        try {
            example.validateInput(-1);
            example.connectToDatabase();
        } catch (ValidationException | DatabaseException e) {
            System.out.println("Caught exception: " + e.getMessage());
        }
    }
}
```

**Output:**
```
Caught exception: Input must be positive.
```

## **7. Best Practices for Custom Exceptions**

1. **Use Meaningful Names**:
   - Name exceptions to clearly convey the type of error (e.g., `InvalidAgeException`, `ProductNotFoundException`).

2. **Provide Descriptive Messages**:
   - Include meaningful messages to help diagnose issues quickly.

3. **Avoid Overusing Custom Exceptions**:
   - Use built-in exceptions like `IllegalArgumentException` or `NullPointerException` where appropriate.

4. **Follow Exception Hierarchy**:
   - Derive custom exceptions from `Exception` or `RuntimeException` based on the use case.

5. **Include Additional Context**:
   - Add properties to exceptions to provide more error-specific details.

6. **Document Exceptions**:
   - Clearly document the purpose and usage of custom exceptions in the codebase.

---

## **8. Summary**

### **Key Concepts**
- **Custom Exceptions**:
  - Extend `Exception` for checked exceptions.
  - Extend `RuntimeException` for unchecked exceptions.
- **Use Cases**:
  - Domain-specific errors (e.g., `InvalidAgeException`).
  - Categorizing exceptions in hierarchies.

### **Advantages**
- Improved readability and maintainability.
- Enhanced error reporting with meaningful messages.

By using custom exceptions effectively, developers can build applications that are easier to debug, maintain, and understand, while providing a better experience for users and other developers.
