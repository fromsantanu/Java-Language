# **Abstraction in Java (Abstract Classes and Interfaces)**

**Abstraction** is one of the core principles of object-oriented programming (OOP) that focuses on **hiding implementation details** and exposing only the essential functionalities. Java provides two mechanisms to achieve abstraction: **abstract classes** and **interfaces**. This chapter explores these concepts, their differences, and practical use cases.

---

## **1. What is Abstraction?**

Abstraction allows a programmer to focus on **what an object does** rather than **how it does it**. It hides the complexity of implementation details and provides a clean and understandable interface.

### **Key Features**
1. **Simplicity**: Reduces complexity by focusing only on relevant details.
2. **Flexibility**: Enables changes to implementation without affecting the interface.
3. **Reusability**: Promotes modular and reusable code by separating concerns.

---

## **2. Abstract Classes**

An **abstract class** is a class that cannot be instantiated. It is designed to be extended by other classes and can include both:
- Abstract methods (declared without a body).
- Concrete methods (declared with a body).

---

### **2.1. Syntax of Abstract Class**
```java
abstract class ClassName {
    // Abstract method (no body)
    abstract returnType methodName(parameters);

    // Concrete method (with body)
    returnType concreteMethod(parameters) {
        // Method body
    }
}
```

---

### **2.2. Example: Abstract Class**
```java
abstract class Shape {
    // Abstract method
    abstract void draw();

    // Concrete method
    void display() {
        System.out.println("This is a shape.");
    }
}

class Circle extends Shape {
    @Override
    void draw() {
        System.out.println("Drawing a circle.");
    }
}

class Rectangle extends Shape {
    @Override
    void draw() {
        System.out.println("Drawing a rectangle.");
    }
}

public class AbstractClassExample {
    public static void main(String[] args) {
        Shape shape1 = new Circle();
        shape1.draw(); // Calls Circle's implementation
        shape1.display();

        Shape shape2 = new Rectangle();
        shape2.draw(); // Calls Rectangle's implementation
        shape2.display();
    }
}
```

**Output:**
```
Drawing a circle.
This is a shape.
Drawing a rectangle.
This is a shape.
```

---

### **2.3. Key Features of Abstract Classes**

1. **Partial Abstraction**:
   - Abstract classes can have both abstract and concrete methods.
2. **Inheritance**:
   - Subclasses must override all abstract methods or be declared abstract themselves.
3. **Constructors**:
   - Abstract classes can have constructors to initialize fields.
4. **Fields**:
   - Can have instance variables (with any access modifier).

---

## **3. Interfaces**

An **interface** is a blueprint for a class that specifies a contract. It contains abstract methods (implicitly `public` and `abstract`) and, optionally, default and static methods.

### **3.1. Syntax of Interface**
```java
interface InterfaceName {
    // Abstract method
    returnType methodName(parameters);

    // Default method
    default returnType defaultMethod(parameters) {
        // Method body
    }

    // Static method
    static returnType staticMethod(parameters) {
        // Method body
    }
}
```

---

### **3.2. Example: Interface**
```java
interface Animal {
    void makeSound(); // Abstract method

    default void eat() { // Default method
        System.out.println("This animal eats food.");
    }
}

class Dog implements Animal {
    @Override
    public void makeSound() {
        System.out.println("Dog barks.");
    }
}

class Cat implements Animal {
    @Override
    public void makeSound() {
        System.out.println("Cat meows.");
    }
}

public class InterfaceExample {
    public static void main(String[] args) {
        Animal dog = new Dog();
        dog.makeSound();
        dog.eat();

        Animal cat = new Cat();
        cat.makeSound();
        cat.eat();
    }
}
```

**Output:**
```
Dog barks.
This animal eats food.
Cat meows.
This animal eats food.
```

---

### **3.3. Key Features of Interfaces**

1. **Complete Abstraction**:
   - Interfaces only declare abstract methods by default (up to Java 7).
   - Java 8 introduced default and static methods in interfaces.
2. **Multiple Inheritance**:
   - A class can implement multiple interfaces.
3. **Fields**:
   - Fields in interfaces are implicitly `public`, `static`, and `final`.
4. **No Constructors**:
   - Interfaces cannot have constructors or instance variables.

---

## **4. Abstract Classes vs Interfaces**

| **Aspect**            | **Abstract Classes**                                  | **Interfaces**                                 |
|------------------------|-------------------------------------------------------|-----------------------------------------------|
| **Inheritance**        | A class can extend only one abstract class.           | A class can implement multiple interfaces.    |
| **Methods**            | Can have abstract and concrete methods.               | Can have abstract, default, and static methods. |
| **Fields**             | Can have instance variables.                         | Only `public static final` constants.         |
| **Constructors**       | Can have constructors.                                | Cannot have constructors.                     |
| **Use Case**           | Best for a base class with shared state or behavior. | Best for defining a contract without implementation. |

---

## **5. Practical Use Case: Abstract Classes and Interfaces**

**Scenario**: Model a payment system with different payment methods.

---

**Solution: Abstract Class for Shared Behavior**
```java
abstract class Payment {
    String transactionId;

    Payment(String transactionId) {
        this.transactionId = transactionId;
    }

    abstract void processPayment();

    void printReceipt() {
        System.out.println("Transaction ID: " + transactionId);
    }
}
```

---

**Solution: Interface for Specific Behavior**
```java
interface Refundable {
    void processRefund();
}
```

---

**Implementation**
```java
class CreditCardPayment extends Payment implements Refundable {
    CreditCardPayment(String transactionId) {
        super(transactionId);
    }

    @Override
    void processPayment() {
        System.out.println("Processing credit card payment.");
    }

    @Override
    public void processRefund() {
        System.out.println("Processing credit card refund.");
    }
}

class PayPalPayment extends Payment {
    PayPalPayment(String transactionId) {
        super(transactionId);
    }

    @Override
    void processPayment() {
        System.out.println("Processing PayPal payment.");
    }
}
```

---

**Main Class**
```java
public class PaymentSystem {
    public static void main(String[] args) {
        Payment creditCardPayment = new CreditCardPayment("CC123");
        creditCardPayment.processPayment();
        creditCardPayment.printReceipt();

        Refundable refundable = (Refundable) creditCardPayment;
        refundable.processRefund();

        Payment payPalPayment = new PayPalPayment("PP456");
        payPalPayment.processPayment();
        payPalPayment.printReceipt();
    }
}
```

**Output:**
```
Processing credit card payment.
Transaction ID: CC123
Processing credit card refund.
Processing PayPal payment.
Transaction ID: PP456
```

---

## **6. Advantages of Abstraction**

1. **Code Reusability**:
   - Abstract classes and interfaces enable modular design.
2. **Decoupling**:
   - Promotes separation of concerns, allowing independent changes to implementation and interface.
3. **Flexibility**:
   - Interfaces support multiple inheritance, offering more design options.

---

## **7. Best Practices**

1. **Use Abstract Classes for Common State**:
   - If classes share fields or partially implemented methods, use an abstract class.
2. **Use Interfaces for Contracts**:
   - Use interfaces to define behavior that multiple unrelated classes must implement.
3. **Minimize Default Methods**:
   - Avoid overusing default methods in interfaces to maintain clear separation of abstraction and implementation.
4. **Leverage Multiple Interfaces**:
   - Implement multiple interfaces to combine behaviors.

---

## **8. Summary**

- **Abstraction**:
  - Hides implementation details and exposes only essential functionalities.
  - Promotes simplicity, flexibility, and modularity.
- **Abstract Classes**:
  - Can have a mix of abstract and concrete methods.
  - Suitable for shared state and behavior.
- **Interfaces**:
  - Define a contract with complete abstraction.
  - Support multiple inheritance through implementation.
- **Use Case**:
  - Abstract classes are ideal for inheritance hierarchies, while interfaces are best for defining contracts.

Mastering abstraction with abstract classes and interfaces ensures clean, maintainable, and extensible Java applications.
